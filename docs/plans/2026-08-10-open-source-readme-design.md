# 开源仓库 README 正规化设计

## 背景

项目已经迁移到 `NightsReimu/pvz-godot`，但仓库根目录仍保留大量逐版本发布说明，缺少 README 和清晰的许可边界。项目计划未来公开源码，因此首页需要同时解决三个问题：让玩家快速理解和下载游戏、让开发者能够构建和测试、让二创素材与东方原曲不被误认为随源码一同开源。

## 方案比较

### 方案 A：纯文字工程文档

只使用标题、目录和代码块。维护成本最低，但无法体现项目已有的二次元 UI 和东方 Boss 内容，对玩家不够直观。

### 方案 B：外部徽章与托管截图

大量使用第三方徽章、统计卡片和外链图片。视觉丰富，但依赖外部服务，链接失效或访问受限时 README 会残缺，也容易显得杂乱。

### 方案 C：自托管视觉素材与分层文档

复用仓库现有标题和界面素材，增加一个轻量、可降级的 SVG 装饰条；正文以清晰的中文结构为主，附简短英文摘要。下载、玩法、构建、测试和许可分别成区，复杂技术信息放入折叠块。

采用方案 C。它既能体现项目风格，又不会让装饰压过文档内容；所有关键视觉都随仓库保存，不依赖不受控的图片服务。

## README 信息架构

README 顶部使用本地标题素材和轻量动态装饰，紧接项目状态、在线体验、Release 下载和英文摘要。主体依次介绍：

1. 游戏定位与当前状态。
2. 主线、每日、娱乐、活动、无尽、基建、强化、抽卡和图鉴等主要模式。
3. 东方 Boss 支线及其程序化弹幕、技能和场景特色。
4. 键鼠和触屏操作方式。
5. Windows、macOS、Android、Web 的获取与运行方法。
6. Godot 4.6 本地开发、目录结构、测试和导出命令。
7. 贡献流程、已知限制、路线图和许可边界。

不保留根目录的逐版本 `RELEASE_NOTES_v*.md`。版本历史以 GitHub Releases、提交历史和标签为准，避免文档重复和根目录持续膨胀。

## 视觉设计

- 使用 `art/home_ui/home_title_text.png` 作为项目标题，不在图片上叠加无法维护的 AI 字体。
- 新增 `docs/readme/readme-accent.svg`，以樱花色、青蓝和金色做缓慢扫光；不使用脚本、外链字体或会阻碍阅读的大面积动画。
- 功能信息优先使用表格与简短条目，不嵌套卡片，不放夸大的统计数字。
- 所有本地图片使用相对仓库路径，保证 GitHub 和离线浏览都能显示。

## 许可设计

许可采用源码与媒体分离：

- 根目录 `LICENSE` 仅授权项目原创源代码使用 MIT License。
- `ASSETS_LICENSE.md` 明确图片、音频、字体、角色、名称和其他媒体不属于 MIT 授权范围。
- 东方 Boss 美术属于 Touhou Project 二次创作素材，使用和再分发应遵循上海爱丽丝幻乐团公布的二次创作规则，并尊重具体素材作者的权利。
- 游戏内东方音乐为东方原作音乐，目前没有确认可随开源仓库再分发的许可。README 和素材声明不得将其称为开源或免版权；正式公开分发前应取得授权或替换为具有明确再分发许可的音乐。
- 项目声明为非官方、非商业同人项目，不暗示上海爱丽丝幻乐团或其他权利人认可。
- 提供权利问题联系和下架处理说明，使用仓库 Issue 作为公开联系入口。

## 质量保证

新增文档质量测试，自动检查：

- 根目录不再存在版本发布说明。
- README 的关键章节、下载链接、构建命令和许可提示齐全。
- README 引用的本地视觉资源存在。
- README、许可文件和文档中不出现旧的 `HecreReed` 仓库链接。
- `LICENSE` 与 `ASSETS_LICENSE.md` 的授权边界明确，不能把东方原曲包含进 MIT。

完成后运行文档质量测试、现有发布工作流测试和 `git diff --check`。本次仅整理文档与许可，不修改游戏版本号，也不创建新的游戏 Release。
