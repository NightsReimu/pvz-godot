# 独立植物 SVG 美术设计

## 目标

让 144 个植物物种及其状态变体拥有基于自身玩法和形态的独立 SVG 轮廓，消除“同一底膜换颜色”的观感，同时保持现有战场、卡槽、图鉴和动画接口不变。

## 现状与问题

植物资源由 `scripts/tools/build_vector_unit_art.py` 生成，`scripts/ui/vector_unit_art.gd` 统一加载 `art/vector/plants/*.svg`。当前生成器把多个物种绑定到 `base`、`pea`、`flower`、`nut` 等完整绘制函数，同一组成员共享主体轮廓，只有颜色和少量装饰不同。状态 SVG 还需要保留坚果受伤、土豆雷未布雷、蘑菇成长/躲藏、食人花咀嚼等可读性。

## 设计

### 形态分层

- 保留通用的低层 SVG 工具，例如路径、渐变、眼睛、叶片、晶体和高光。
- 每个物种 recipe 由独立的主体绘制函数或独立的形态分支组成；recipe 可以调用工具，但不能只调用另一个植物的完整主体再改颜色。
- 每个植物至少有一个专属轮廓锚点：炮口/弹体、花瓣排列、菌盖边缘、坚果外壳结构、投掷臂、叶脉、果皮分瓣、武器装备或元素核心。
- 同系列植物保留家族关系，但通过数量、比例、姿态、材质和器官位置区分，保证卡槽小尺寸下仍可识别。

### 状态与运行时兼容

- 继续生成现有状态文件名，避免改变 `vector_unit_art.gd` 和运行时调用协议。
- 受伤状态只叠加裂纹/破损，不替换植物主体。
- 动作由现有运行时变换继续控制，SVG 不引入会改变布局的外部尺寸。

### 验证

- 扩展向量资源测试，检查 144 个物种均存在可加载 SVG、画布边缘留白和有效占用区域。
- 扩展视觉身份测试，覆盖不同家族的轮廓差异，并检查状态变体相对基础形态确实发生变化。
- 运行 headless 资源/逻辑回归；在可用显示渲染器上运行植物身份像素测试和 UI 布局测试。
- 生成全量 SVG 后检查 manifest 与 `Defs.PLANTS` 一致，避免漏资源或多余资源。

## 发布
