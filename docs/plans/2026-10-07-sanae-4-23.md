## GLES crash: exact reproducer and patch

Primary upstream diagnosis and fix: [Godot#117725](https://github.com/godotengine/godot/pull/117725), cherry-picked for [Godot4.6.3](https://godotengine.org/download/archive/4.6.3-stable/). At an exact multiple of16384 GLES item instances, opening the next batch resets its index to0. The old empty-index early return skipped rendering and clearing prior batches; freeing old polygon commands then left stale references for the next frame. Raising an application bullet cap cannot fix that engine lifetime bug.

| Real macOS GLES probe | Engine | Native result |
| --- | --- | --- |
| Valid six-point polygons49152→32769 | 4.6.0 /89cea1439 | Exit134, `pb null` at1333 and `Index3/size3` fatal, matching the reported signature |
| Same case with counts49153→32770 | 4.6.0 | Exit0, no diagnostics, current draw counts correct |
| Identical exact-capacity case | 4.6.3 /7d41c59c4 | Exit0, no diagnostics, current draw counts correct |
| Actual4-19 Hard finale,18 catalogue-stat fusions; natural player defeat at276.55s;900 subsequent GPU flushes | 4.6.3 | Exit0, no diagnostics; peak480 bullets and24299 objects, retained defeated scene18830 objects |

The last case starts from an explicit mature formation snapshot, not a paid complete route. It uses real game damage/defeat without fakeHP, synthetic polygon padding or forced loss. The exact user gameplay sequence was not independently reproduced; the renderer minimal reproducer matches its fatal signature and demonstrates the causal fix. Native rendering uses real `RenderingServer.force_draw(true)` in the test, avoiding false conclusions from an occluded-window `frame_post_draw` wait. Production rendering does not force GPU draws.

All four build targets pin4.6.3 editor/templates. Source startup rejects unsupported engine versions before combat initialization and presents an update notice; the Python/macOS launcher selects an installed supported engine without replacing the system engine. The machine's existing `/Applications/Godot.app` remains4.6.0. Updating the project alone does not patch that executable.
